# 承認ワークフロー・電子契約管理システム（approval-workflow-demo）

紙とハンコで行っている月間100〜150件の承認業務を電子化し、**稟議・捺印申請の多段階承認 → 電子契約での締結 → 契約書の一元管理 → 会計システム連携**までを1つのシステムで完結させる提案用デモです。

- **性格: 業務システム型**（CLAUDE.md §2-2）。UI文言・システム名・画面タイトルはすべて日本語です。
- 公開URL: https://ict-o.github.io/client-demo-apps/approval-workflow-demo/

## 目的

商談時に「ワークフロー・電子契約・契約書管理を別々のサービスで組み合わせるのではなく、1つの画面で完結できる」ことを実機操作で示すためのデモです。
**電子契約は本システム内で完結し、外部システムとの連携は会計システムのみ**という構成を、画面上で確認できるようにしています。

## はじめて開く方へ（操作ガイド）

- 画面を開くと案内ダイアログが表示され、**ガイド付きツアー（全14ステップ・約5分）**を開始できます。
  ツアーは各ステップで該当画面へ自動で移動し、注目してほしい箇所をハイライトします。いつでも「終了」で自由操作に戻れます。
- ヘッダー右上の「操作ガイド（ツアー）」ボタン、またはメニューの「操作ガイド」からいつでも開始できます。
- メニューの **「操作ガイド」画面**には、シナリオ別の操作手順（各手順から該当画面へ移動可能）・画面一覧・登場する担当者・よくある質問をまとめています。

## 想定ユースケース（不動産関連の契約を扱う企業）

- 捺印申請・稟議書を電子申請し、内容に応じた承認ルートで多段階承認する
- 承認者が出張・休暇で不在でも、代理承認により書類を滞留させない
- 承認完了後、そのまま電子契約で締結する（相手先が電子契約に未対応の場合は捺印手配 → 原本スキャン取込へ分岐）
- 署名の進捗・期限・リマインド・監査ログを管理し、締結後は合意締結証明書を発行する
- 締結した契約書を、契約期限・相手先企業名・契約内容・物件情報・賃料などの主要項目つきで一元管理する
- 紙で届いた契約書は AI が主要項目を抽出し、相手先企業名と契約内容で自動振り分けして登録する
- 契約金額・賃料を会計システムへ連携する（本システム唯一の外部連携）

## 実演フロー（この順に画面上で最後まで操作できます）

1. **ダッシュボード** — 承認待ち件数・3日以上の滞留・電子契約の署名待ち・更新期限が近い契約・電子化率の推移を確認する
2. **申請一覧 → 申請詳細** — 滞留している申請を開き、多段階の承認ルートと現在の承認者（不在中の表示）を確認する
3. **代理承認** — 画面右上の「利用者」を代理承認者に切り替え、承認または差戻しを実行する（履歴に代理承認として記録）
4. **締結方法の選択** — 最終承認まで進んだ申請で締結方法を選ぶ
   - 相手先が電子契約に対応 → 「電子契約で締結する」→ 送信準備へ
   - 未対応 → 「紙で締結する（捺印手配）」→ 捺印依頼 → 原本スキャン取込
5. **電子契約の送信準備（3ステップ）** — 契約内容の確認 → 署名者・本人確認方法・署名期限の設定 → **書類上をクリックして署名欄を配置** → 送信
6. **電子契約 詳細** — 署名の進捗・監査ログ・書類のハッシュ値を確認し、リマインド送信／期限延長して再送／送信取消を実行する
7. **署名** — 「相手先の署名画面を開く」で受領者側の画面（メール → アクセスコード → 内容確認 → 署名）を実演し、続けて「自社の署名を実行する」で締結を確定する
8. **契約書管理** — 締結した契約書が自動登録され、相手先・物件・契約種別で検索／期限順に並び替えできる
9. **契約書詳細** — 主要項目・自動付与タグ・締結情報（合意締結証明書）を確認し、会計システムへ連携する／更新稟議を起票する
10. **外部連携** — 会計システムの接続状態・未連携の契約書・連携ジョブ履歴（失敗時の再連携）・連携項目の対応表・機能ごとの実現方式を確認する
11. **契約書取込（AI項目抽出）** — スキャン済PDFを選び、AI抽出 → 抽出確度つきの確認画面で修正 → 自動振り分け先を確認して登録する
12. **承認ルート設定** — 判定条件の一覧、不在・代理承認者の設定、承認ルートのシミュレーション

## 主な機能

| 機能 | 内容 |
|------|------|
| 内容に応じた承認ルート設定 | 申請種別・契約種別・金額から承認段階を自動判定（申請画面で即時プレビュー） |
| 多段階承認 | 部門長 → 法務確認 → 管理本部長 → 代表取締役の段階を条件に応じて組み立て |
| 不在時の代理承認 | 承認者を不在に設定すると代理承認者が処理でき、滞留を防止 |
| 電子契約（送信準備） | 署名者・署名順・本人確認方法（メール認証／アクセスコード併用）・署名期限を設定し、書類上をクリックして署名欄を配置 |
| 電子契約（署名・締結） | 相手先の署名画面をデモで再現。署名拒否・送信取消・期限切れ・期限延長して再送まで分岐を実装 |
| 締結証明・監査ログ | 誰がいつどこから開封・署名したかを記録し、締結後は合意締結証明書（書類のハッシュ値つき）を表示 |
| ドキュメント管理 | 契約期限・相手先企業名・契約内容・物件情報・賃料を項目管理し、検索・絞り込み・並び替えが可能 |
| AI項目抽出 | 取込ファイルから主要項目を抽出し、項目ごとの抽出確度を表示。修正して登録できる |
| 自動振り分け | 相手先企業名と契約種別から保管フォルダとタグを自動決定 |
| 会計システム連携 | 連携内容の事前確認・連携ジョブ履歴・失敗ジョブの再連携・項目の対応表・疎通確認 |
| 操作ガイド | ガイド付きツアー（全14ステップ）とシナリオ別の操作手順ページ |

## 外部連携の範囲

**外部システムと接続するのは会計システムのみ**です。それ以外はすべて本システム内で完結します。

| 機能 | 区分 | 実現方式 |
|------|------|----------|
| 会計システム連携 | 外部連携 | 契約金額・賃料・支払期間・相手先・契約種別を連携（契約書本文・署名情報は送信しない） |
| 承認ワークフロー | 内部完結 | 本システム内で処理 |
| 電子契約（署名依頼・署名・締結） | 内部完結 | 本システム内で処理（外部の電子契約サービスは使いません） |
| 締結証明・監査ログ・タイムスタンプ | 内部完結 | 本システム内で生成・保管 |
| 契約書のAI項目抽出・自動振り分け | 内部完結 | 本システム内の抽出処理 |
| 契約書の保管・検索 | 内部完結 | 本システム内に保管 |
| 署名依頼・リマインドのメール送信 | 内部完結 | 本システムのメール送信機能 |

## 使用技術

- React 19 / TypeScript / Vite（React Router v7・HashRouter）
- 状態はブラウザのメモリ内のみで保持（バックエンドなし）。リロードすると初期状態に戻ります。

## ビルド方法

```bash
cd approval-workflow-demo
npm install
npm run build
```

- 出力はデモ直下の `index.html` と `assets/`（`dist/` は使いません）。
- ビルド後は `index.html` と `assets/` を必ずセットでコミットしてください。
- ビルドすると開発用エントリの `index.html` はビルド成果物で上書きされます。再ビルドする場合は、`<script type="module" src="/src/main.tsx"></script>` を読み込む開発用の `index.html` に戻してから実行してください。

## データについて

- 表示される企業名・担当者名・物件名・金額・契約内容・ファイル名・メールアドレス・IPアドレスは**すべて架空のサンプル**です。
  （メールアドレスは説明用に予約された `example.jp`、IPアドレスは文書用に予約された範囲を使用しています）
- 書類のハッシュ値・タイムスタンプは画面表示のための疑似値で、暗号処理は行っていません。
- 実在の顧客名・案件名・実データ・認証情報は一切含みません。
