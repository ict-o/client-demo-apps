# 契約ワークフロー管理システム（フェーズ1・2）／approval-workflow-phase1-2-demo

紙とハンコで行っている契約業務の電子化を、**フェーズ1とフェーズ2の機能範囲で**提案するためのデモです。
`approval-workflow-phase1-demo`（フェーズ1のみ）と同じ画面デザイン・操作感のまま、フェーズ2の6項目を追加しています。フェーズ3の機能は含めていません。

- **性格: 業務システム型**（CLAUDE.md §2-2）。UI文言・システム名・画面タイトルはすべて日本語です。
- 公開URL: https://ict-o.github.io/client-demo-apps/approval-workflow-phase1-2-demo/

## 目的

商談で「フェーズ2まで実施すると何がどう変わるのか」を実機操作で示すためのデモです。
フェーズ1版と並べて見せることで、追加投資で得られる差分（手入力がAI抽出になる、条項の文言から契約書を探せる、証跡が残る）をその場で比較できます。

## フェーズ2で追加した機能（フェーズ1版との差分）

| フェーズ2の項目 | このデモでの実装 |
|-----------------|------------------|
| 電子契約拡張機能（複数署名・署名順・再送・期限管理等） | 署名者を必要なだけ追加でき（3名以上の複数署名）、「上へ／下へ」で署名順を並び替え。書類上をクリックして署名欄を自由に配置。署名期限の設定と残り日数表示、リマインド送信、期限を延長しての再送、送信取消、相手先による署名拒否まで実装 |
| OCRによる紙契約書読み取り | 取り込んだPDFの本文を読み取り、読み取り文字数と本文を画面で確認できる。読み取った本文は契約書に保存され、全文検索の対象になる |
| AIによる契約書主要項目の自動抽出 | 相手先・契約種別・物件・月額賃料・契約金額・契約期間・自動更新を**項目ごとの抽出確度つき**で抽出。確度の低い項目は色付きで表示し、修正して登録できる |
| 契約相手先・契約内容による自動振り分け | 保管フォルダとタグを相手先企業名・契約種別・物件の有無・賃料の有無から自動決定。登録前にプレビューできる |
| 高度な全文検索 | 契約書**本文を含む全文検索**。スペース区切りのAND検索、「-語」による除外検索、契約金額の下限指定に対応し、本文にヒットした場合は該当箇所を抜き出して強調表示する |
| 監査ログ・証跡・セキュリティ強化 | ログイン（失敗を含む）・権限変更・承認・電子契約の送信/署名/取消・契約書登録・CSV出力を、実行者・日時・アクセス元（IPアドレス／端末）・成否つきで記録する**監査ログ画面**を追加。管理者のみ閲覧可。電子契約にはアクセスコードによる本人確認を追加 |

## このデモに含めていない機能（フェーズ3の対象）

| 機能 | 内容 |
|------|------|
| 過去契約書・既存データ移行 | 既存の契約書データの一括取込 |
| 契約更新・期限管理・アラート強化 | 更新期限の通知と更新稟議の自動起票 |
| AI抽出精度向上・自動登録 | 抽出精度の改善と、確認なしでの自動登録 |
| ワークフロー追加・運用ルール拡張 | 承認ルートの種類追加と運用ルールの拡張 |

同じ内容は画面内の「操作ガイド」にも掲載しているため、商談中でもその場で示せます。

## 権限（ロール）

| 権限 | できること |
|------|-----------|
| システム管理者 | 全機能に加えて、利用者・組織・権限の管理、承認ルート設定、**監査ログの閲覧** |
| 承認者 | 申請の起票、自分が承認者の段階の承認・差戻し、CSV出力 |
| 申請者 | 申請の起票、契約書の取込・登録・検索（承認はできない） |
| 閲覧者 | 申請・契約書の閲覧のみ |

権限を変えると、その利用者に見えるメニューと押せるボタンが実際に変わります。

## はじめて開く方へ（操作ガイド）

- 最初にログイン画面が表示されます。**デモ用アカウントの行を選ぶとログインIDとパスワードが入力されます。**
  パスワードは全アカウント共通のデモ用の値で、ログイン画面に表示しています（架空のアカウントです）。
- ログイン後に案内ダイアログが表示され、**ガイド付きツアー（全14ステップ・約6分）**を開始できます。
- メニューの **「操作ガイド」画面**には、シナリオ別の操作手順・画面一覧・**フェーズ2で追加した機能**・**フェーズ3に回した機能**・登場する担当者・よくある質問をまとめています。

## 実演フロー（この順に画面上で最後まで操作できます）

1. **ログイン** — デモ用アカウントを選んでログインする（無効アカウントではログインできず、失敗も監査ログに残る）
2. **申請一覧**（ログイン後の最初の画面）— 稟議書と捺印申請を1つの一覧で確認し、滞留日数・現在の承認者で絞り込む
3. **申請詳細 → 承認** — 承認ルートと現在の承認者を確認し、利用者を切り替えて承認または差戻しを実行する
4. **締結方法の選択** — 電子契約で締結する／紙で締結する（捺印手配）に分岐する
5. **電子契約の送信準備（3ステップ）** — 契約内容の確認 → **署名者の追加・署名順の並び替え・アクセスコード・署名期限の設定** → **書類上をクリックして署名欄を配置** → 送信
6. **電子契約 詳細** — 署名の進捗・監査ログ・書類のハッシュ値を確認し、リマインド送信／期限延長して再送／送信取消を実行する
7. **署名** — 相手先の署名画面（メール → アクセスコード → 内容確認 → 署名）を実演し、続けて自社の署名で締結を確定する
8. **3者署名の案件**（ES-2026-0032）— 3名の署名者を順番に回している案件で、複数署名と署名順を見せる
9. **契約書取込** — PDFを選び、**OCR読み取り → AI項目抽出**（確度つき）→ 修正 → **自動振り分け先を確認**して登録する
10. **契約書管理（全文検索）** — 「原状回復」で本文検索、「賃貸借 -サクラ台」でAND検索と除外検索を試す
11. **会計システム連携** — 未出力の契約書を選び、CSVをプレビューして出力する
12. **監査ログ** — いま行った操作が記録されていることを、区分の絞り込みと「失敗した操作のみ表示」で確認する
13. **利用者・権限管理** — 権限を変更し、使えるメニューと操作が変わることを確認する

## 外部連携の範囲

**外部システムと接続するのは会計システムのみ**で、**CSVファイルの受け渡し**で連携します。それ以外はすべて本システム内で完結します。
出力するのは契約金額・月額賃料・支払期間・相手先・契約種別で、**契約書の本文・添付ファイル・署名情報は出力しません。**

## サンプルデータの日付について

サンプルは基準日（2026-08-20）時点の業務状況として作成し、**画面表示時に当日基準へ日付をずらしています**（`src/utils/demoDate.ts`）。
このため、いつ開いても滞留日数や署名期限が現実的な値で表示されます。

## 使用技術

- React 19 / TypeScript / Vite（React Router v7・HashRouter）
- 状態はブラウザのメモリ内のみで保持（バックエンドなし）。リロードすると初期状態に戻ります。
- 認証・OCR・AI抽出はデモ用の画面上の処理のみで、実際の認証基盤・文字認識・AIモデルは動作していません。

## ビルド方法

```bash
cd approval-workflow-phase1-2-demo
npm install
npm run build
```

- 出力はデモ直下の `index.html` と `assets/`（`dist/` は使いません）。
- ビルド後は `index.html` と `assets/` を必ずセットでコミットしてください。
- ビルドすると開発用エントリの `index.html` はビルド成果物で上書きされます。再ビルドする場合は、`<script type="module" src="/src/main.tsx"></script>` を読み込む開発用の `index.html` に戻してから実行してください。

## データについて

- 表示される企業名・担当者名・物件名・金額・契約内容・契約書本文・ファイル名・メールアドレス・IPアドレス・ログインID・パスワードは**すべて架空のサンプル**です。
  （メールアドレスは説明用に予約された `example.jp`、IPアドレスは文書用に予約された範囲を使用しています）
- 書類のハッシュ値・タイムスタンプは画面表示のための疑似値で、暗号処理は行っていません。
- 実在の顧客名・案件名・実データ・認証情報は一切含みません。
