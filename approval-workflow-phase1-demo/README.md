# 契約ワークフロー管理システム（フェーズ1）／approval-workflow-phase1-demo

紙とハンコで行っている契約業務の電子化を、**フェーズ1の機能範囲に絞って**提案するためのデモです。
`approval-workflow-demo`（全機能版）と同じ画面デザイン・操作感のまま、フェーズ1に含まれない機能を外し、フェーズ1で必要になる**認証・ログイン／利用者・組織・権限管理**を追加しています。

- **性格: 業務システム型**（CLAUDE.md §2-2）。UI文言・システム名・画面タイトルはすべて日本語です。
- 公開URL: https://ict-o.github.io/client-demo-apps/approval-workflow-phase1-demo/

## 目的

商談で「フェーズ1で何ができるようになるのか」を実機操作で示すためのデモです。
フェーズ2以降で追加する機能は画面から外し、代わりに操作ガイド内で「このフェーズに含めていない機能」として一覧で示しています。
どこまでが今回の見積範囲かを、口頭説明ではなく画面で確認できます。

## フェーズ1の対象機能（このデモに入っているもの）

| フェーズ1の項目 | このデモでの画面 |
|-----------------|------------------|
| 認証・ログイン／ユーザー・組織・権限管理 | ログイン画面、利用者・権限管理 |
| 社内ワークフロー機能 | 申請一覧・申請詳細・新規申請 |
| 内容に応じた承認ルート設定＋多段階承認 | 新規申請のルートプレビュー、承認ルート設定 |
| 紙契約書のPDF登録・ドキュメント管理 | 紙契約書の登録 |
| 契約台帳・基本検索 | 契約書管理（検索・絞り込み・並び替え） |
| 電子契約基本機能（締結・基本証跡・契約書保管） | 電子契約（送信準備・署名・締結・合意締結証明書・操作履歴） |
| 紙／電子契約の一元管理・ステータス管理 | 契約書管理（電子契約・スキャン原本を1つの台帳で管理） |

> 「要件定義・基本設計」「テスト・導入・操作説明」は作業項目のため、画面はありません。

## フェーズ1に含めていない機能（フェーズ2・3の対象）

フェーズ表の区分に合わせて、次の機能は画面に含めていません。

| フェーズ | 機能 | このデモでの扱い |
|----------|------|------------------|
| 2 | 電子契約拡張機能（複数署名・署名順・再送・期限管理等） | 署名者は相手先1名＋当社1名の固定、署名順は「相手先 → 当社」で固定。署名期限・リマインド・再送・送信取消は無し |
| 2 | OCRによる紙契約書読み取り | 紙契約書はPDFを選んで契約情報を手入力（ファイル名からの仮入力のみ） |
| 2 | AIによる契約書主要項目の自動抽出 | 同上（自動抽出は行わない） |
| 2 | 契約相手先・契約内容による自動振り分け | 保管フォルダは登録時に手動で選択 |
| 2 | 高度な全文検索 | 契約台帳の項目（相手先・物件・契約種別・契約名）を対象にした基本検索のみ |
| 2 | 監査ログ・証跡・セキュリティ強化 | 日時・操作者・操作内容の基本の操作履歴のみ（IPアドレス・端末の記録は無し） |
| 3 | 過去契約書・既存データ移行 | 無し |
| 3 | 契約更新・期限管理・アラート強化 | 契約満了日は台帳項目として表示するのみ。更新期限のアラート・更新稟議の起票は無し |
| 3 | AI抽出精度向上・自動登録 | 無し |
| 3 | ワークフロー追加・運用ルール拡張 | 承認ルートは判定条件の確認とシミュレーションまで |
| 3 | 管理ダッシュボード・集計機能 | ダッシュボード画面と集計グラフは無し。ログイン後は申請一覧が最初の画面 |
| 3 | 追加外部システム連携・運用改善 | 外部連携は会計システムへのCSV出力のみ |

同じ内容は画面内の「操作ガイド」にフェーズ区分つきで掲載しているため、商談中でもその場で示せます。

## 権限（ロール）

利用者・権限管理で付与する権限は4種類です。**権限を変えると、その利用者に見えるメニューと押せるボタンが実際に変わります。**

| 権限 | できること |
|------|-----------|
| システム管理者 | 全機能に加えて、利用者・組織・権限の管理と承認ルート設定 |
| 承認者 | 申請の起票、自分が承認者の段階の承認・差戻し、CSV出力 |
| 申請者 | 申請の起票、契約書の登録・検索（承認はできない） |
| 閲覧者 | 申請・契約書の閲覧のみ |

## はじめて開く方へ（操作ガイド）

- 最初にログイン画面が表示されます。**デモ用アカウントの行を選ぶとログインIDとパスワードが入力されます。**
  パスワードは全アカウント共通のデモ用の値で、ログイン画面に表示しています（架空のアカウントです）。
- ログイン後に案内ダイアログが表示され、**ガイド付きツアー（全12ステップ・約4分）**を開始できます。
- ヘッダー右上の「操作ガイド（ツアー）」ボタン、またはメニューの「操作ガイド」からいつでも開始できます。
- メニューの **「操作ガイド」画面**には、シナリオ別の操作手順・画面一覧・**フェーズ2/3に回した機能の一覧**・登場する担当者・よくある質問をまとめています。

## 実演フロー（この順に画面上で最後まで操作できます）

1. **ログイン** — デモ用アカウントを選んでログインする（無効アカウントではログインできないことも確認できる）
2. **申請一覧**（ログイン後の最初の画面）— 稟議書と捺印申請を1つの一覧で確認し、滞留日数・現在の承認者で絞り込む
3. **申請詳細** — 滞留している申請を開き、多段階の承認ルートと現在の承認者を確認する
4. **承認** — 画面右上の「利用者」を現在の承認者に切り替え、承認または差戻しを実行する
5. **締結方法の選択** — 最終承認まで進んだ申請で締結方法を選ぶ
   - 相手先が電子契約に対応 → 「電子契約で締結する」→ 送信準備へ
   - 未対応 → 「紙で締結する（捺印手配）」→ 捺印依頼 → 原本の登録へ
6. **電子契約の送信準備（2ステップ）** — 契約内容の確認 → 相手先の署名者を入力 → 契約書プレビューを確認して送信
7. **電子契約 詳細** — 署名の進捗・操作履歴・書類のハッシュ値を確認する
8. **署名** — 「相手先の署名画面を開く」で受領者側の画面（メール → 内容確認 → 署名）を実演し、続けて「自社の署名を実行する」で締結を確定する
9. **契約書管理** — 締結した契約書が自動登録され、相手先・物件・契約種別で検索／満了日順に並び替えできる
10. **紙契約書の登録** — 受領したPDFを選び、契約情報を入力して保管フォルダを指定し、契約台帳へ登録する
11. **契約書詳細** — 主要項目・締結情報（合意締結証明書）を確認し、CSV出力する
12. **会計システム連携** — 未出力の契約書を選び、CSVの内容をプレビューして出力し、出力履歴に残ることを確認する
13. **利用者・権限管理** — 権限を変更し、その利用者に見えるメニューと押せるボタンが変わることを確認する
14. **承認ルート設定** — 判定条件の一覧と、承認ルートのシミュレーション

## 外部連携の範囲

**外部システムと接続するのは会計システムのみ**で、フェーズ1では**CSVファイルの受け渡し**で連携します。それ以外はすべて本システム内で完結します。
出力するのは契約金額・月額賃料・支払期間・相手先・契約種別で、**契約書の本文・添付ファイル・署名情報は出力しません。**

## サンプルデータの日付について

サンプルは基準日（2026-08-20）時点の業務状況として作成し、**画面表示時に当日基準へ日付をずらしています**（`src/utils/demoDate.ts`）。
このため、いつ開いても滞留日数や契約期間が現実的な値で表示されます。

## 使用技術

- React 19 / TypeScript / Vite（React Router v7・HashRouter）
- 状態はブラウザのメモリ内のみで保持（バックエンドなし）。リロードすると初期状態に戻ります。
- 認証はデモ用の画面上の処理のみで、実際の認証基盤・パスワード管理は行っていません。

## ビルド方法

```bash
cd approval-workflow-phase1-demo
npm install
npm run build
```

- 出力はデモ直下の `index.html` と `assets/`（`dist/` は使いません）。
- ビルド後は `index.html` と `assets/` を必ずセットでコミットしてください。
- ビルドすると開発用エントリの `index.html` はビルド成果物で上書きされます。再ビルドする場合は、`<script type="module" src="/src/main.tsx"></script>` を読み込む開発用の `index.html` に戻してから実行してください。

## データについて

- 表示される企業名・担当者名・物件名・金額・契約内容・ファイル名・メールアドレス・ログインID・パスワードは**すべて架空のサンプル**です。
  （メールアドレスは説明用に予約された `example.jp` を使用しています）
- 書類のハッシュ値・タイムスタンプは画面表示のための疑似値で、暗号処理は行っていません。
- 実在の顧客名・案件名・実データ・認証情報は一切含みません。
