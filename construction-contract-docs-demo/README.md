# 工事契約書類管理システム デモ

建設工事に関する**注文契約書類（見積書・注文書・注文請書・基本契約書／約款）を1案件1セットで管理し、
見積書の内容から関連書類を自動生成する Web システム**の提案用デモです。

製造業を営みながら工事事業も手掛ける企業で、建設業法に基づく書類管理体制を新たに整備するケースを想定しています。
見積書を作成した時点で注文書・注文請書・約款が自動生成され、顧客名・工事内容・請負代金・工期・契約条件が
すべての書類に自動反映されます。書類は案件単位で一式にまとめて出力・保管できます。

- **性格: 業務システム型**（提案先の社内業務を置き換える／補助するシステム。UI 文言はすべて日本語）
- **公開URL**: https://ict-o.github.io/client-demo-apps/construction-contract-docs-demo/

## 目的

- 建設業法に準拠した書類管理体制の構築（第19条第1項の記載事項をシステム側で担保する）
- 見積書作成後の関連書類（注文書・注文請書・約款）作成業務の効率化
- 法対応のために現場へ新たな作業負荷を積み増さないこと（入力は見積書1回、以降は自動反映）
- 法的指導を受けるリスクの回避（不足項目を画面上で可視化する）

## 想定ユースケース

- **受注案件**: 発注者（得意先）から受注する工事。見積書を提出し、注文書に押印をもらい、注文請書を発行して契約成立まで進める。
  注文書を発行しない取引先に対しては、自動生成した注文書へ記名押印をいただくだけで法定の書類一式が揃う。
- **発注案件**: 協力会社（下請）へ発注する工事。受領した見積書をもとに注文書を発行し、注文請書の返送を受けて契約成立とする。
  中小の協力会社との取引でも同じ書式・同じチェック基準で書類を整備できる。
- 書類一式（4点）を1ファイルにまとめて出力し、案件番号で保管する。

## 主な画面・機能

| 画面 | 内容 |
|------|------|
| 工事案件一覧 | KPI（見積提出済／注文書受領済／受注確定／書類不備あり）から絞り込み。案件番号・工事名・取引先・工事場所での検索、ステータス／取引区分の絞り込み、更新日・請負金額・完成予定日での並び替え。書類4点の作成状況と法令チェックの充足数を一覧で確認できる |
| 新規見積作成 | 3ステップ（基本情報 → 見積明細 → 契約条件・確認）。取引先を選ぶと所在地・担当者・支払条件をマスタから自動反映。明細の数量・単価を変えると小計・消費税・合計が即時再計算され、法定記載事項の充足率もその場で表示される |
| 案件詳細 | 「次のアクション」を常に提示。書類セット／見積明細／契約条件／法令チェック／履歴の5タブ |
| 　└ 書類セット | 見積書・注文書・注文請書・約款の状況を1画面で管理。**見積書から3書類を自動生成**、送付・押印受領の登録、帳票プレビュー（印刷対応）、書類一式（4点）の1ファイル出力 |
| 　└ 見積明細 | 明細の追加・編集・削除と値引の設定。変更すると請負代金が再計算され、自動生成済み書類に「再生成が必要」の警告が出る |
| 　└ 契約条件 | 建設業法第19条第1項の記載事項（着手・完成時期、施工しない日、前金払、検査・引渡し、支払、契約不適合責任、遅延利息、紛争解決 等）を入力。保存すると各書類の記載へ反映される |
| 　└ 法令チェック | 記載事項17項目（発注案件は下請の建設業許可確認を加えた18項目）の充足状況を○×と充足率で表示。不足項目は入力すべき内容を日本語で提示 |
| 取引先マスタ | 発注者・協力会社の登録／編集。会社名・所在地・支払条件・建設業許可番号を管理し、書類へ自動反映。許可番号未登録の協力会社は「要確認」として表示 |

## 実演フロー（この順で最後まで操作できます）

1. **工事案件一覧**を表示（進行中の案件が多様なステータスで並ぶ）。KPI「書類不備あり」を押して対象案件だけに絞り込む
2. 「＋ 新規見積を作成」→ 取引区分と取引先を選択（**所在地・支払条件がマスタから自動反映**される）→ 工事名・場所・内容を入力
3. 「見積明細」で数量・単価を入力（**合計・消費税が即時再計算**される）→ 「契約条件」で着手日・完成日・支払条件などを入力（**法定記載事項の充足率がその場で変化**）→ 「この内容で見積書を作成する」
4. 作成された案件詳細で「見積書を送付する」→ ステータスが「見積提出済」に変わる
5. 「見積書から3書類を自動生成する」→ **注文書・注文請書・基本契約書（約款）が採番され、見積内容が反映された状態で作成される**
6. 各書類の「プレビュー」で記載内容を確認（そのまま印刷も可能）
7. 「押印済み注文書の受領を登録する」→「注文請書を送付して受注確定にする」→ ステータスが「受注確定」へ
8. 「見積明細」タブで数量を変更 → 「見積内容が変更されています」の警告から**3書類を再生成**
9. 「法令チェック」タブで充足状況を確認 → 不足があれば「契約条件」タブで入力して解消
10. 「書類一式（4点）を1ファイルで出力」→ ファイル構成を確認して出力（履歴に記録される）
11. 「履歴」タブで誰がいつ何をしたかを確認。「取引先マスタ」で会社情報を編集すると、書類の記載へ反映される

> 入力・操作した内容は画面上の状態に即時反映されます。ブラウザを再読み込みすると初期のサンプルデータに戻ります（永続化はしていません）。

## 使用技術

- React 19 + TypeScript
- Vite（`base` をサブパスに設定し、GitHub Pages でそのまま閲覧できる静的ファイルを生成）
- React Router v7（`HashRouter`）
- バックエンド・外部サービスへの依存なし（フロントエンドのみで完結）

## ビルド方法

```bash
npm install
npm run build
```

- ビルド成果物（デモ直下の `index.html` と `assets/`）が公開対象です。`src/` は開発用ソースです。
- `main` へマージされると GitHub Pages に公開されます。

## データについて

- 表示されている**会社名・担当者名・住所・電話番号・工事内容・金額・日程はすべて架空のサンプル**です。
  会社名は固有部分を「〇〇」で伏せています。
- 実在の顧客・案件・個人情報や、認証情報・実データは一切含みません。**顧客固有の実装も含みません。**
- 自社側の会社名「株式会社〇〇製作所」、建設業許可番号、担当者名も架空です。
- 画面に表示される法令の条文・条項名は、システムの機能（記載事項チェック）を説明するための表示であり、
  法的助言を目的とするものではありません。実際の運用にあたっては専門家にご確認ください。
