# 工事契約書類管理システム デモ

**Excel で作った見積書を取り込むと、注文書・注文請書・基本契約書（約款）が自動で作られ、
案件ごとに書類4点を1セットで管理できる Web システム**の提案用デモです。

製造業を営みながら工事事業も手掛ける企業で、建設業法に基づく書類管理体制を新たに整備するケースを想定しています。
見積書は今までどおり Excel で作り、それをそのままシステムに取り込みます。取引先名・工事内容・請負代金は
取り込んだ内容から各書類へ自動で反映されるため、担当者が入力するのは**工期・支払い方法など4項目だけ**です。

- **性格: 業務システム型**（提案先の社内業務を置き換える／補助するシステム。UI 文言はすべて日本語）
- **公開URL**: https://ict-o.github.io/client-demo-apps/construction-contract-docs-demo/

## 設計の考え方

商談相手は営業部門・業務部門の担当者で、パソコン操作に不慣れな方も使います。そのため次の方針で作っています。

- **見積書はシステムで作らない。** 既存の Excel 見積書を取り込む方式にし、二重入力をなくしています。
- **入力項目を4つに絞る。** 検査・引渡し・遅延利息・紛争解決などの法定記載事項は**約款テンプレートに定型条項として持たせ**、
  担当者が入力する必要をなくしています。
- **お客様から受注する工事に絞る。** 取引の流れは「注文書をもらう → 注文請書を出す」の1通りだけです。
- **画面を減らす。** メニューは3つ（工事案件の一覧／見積書を取り込む／取引先）、案件詳細のタブは3つだけです。
- **「次にやること」を常に1つだけ大きく出す。** 進み具合を4ステップで示し、迷わず次の操作に進めます。
- **大きな文字・大きなボタン。** 本文16px、ボタンの高さ48px以上（主要ボタンは56px）を基準にしています。
- **専門用語はやさしい言葉を添える。** 例：「注文請書＝注文をお請けしたことを伝える書類」。

## 主な画面・機能

| 画面 | 内容 |
|------|------|
| 工事案件の一覧 | 「対応が必要／進行中／工事完了」の3つのタイルで絞り込み。工事名・取引先名・案件番号での検索。書類のそろい具合（4点中何点か）と入力の不足件数を一覧で確認できる |
| 見積書を取り込む | ①共有フォルダに保存された見積書ファイルを選ぶ → ②読み取り結果（取引先・工事名・工事場所・工事内容・明細・金額）を確認し、工期・支払い方法など**4項目だけ入力**して登録 |
| 案件詳細 | 進み具合を4ステップで表示。「次にやること」を1つだけ大きく提示。「書類に必要な項目」がそろっているかを常時チェック |
| 　└ 書類 | 見積書・注文書・注文請書・約款の状況を1画面で確認。各書類の中身をプレビュー（印刷対応）。書類4点を1つのファイルにまとめて出力 |
| 　└ 見積書の内容 | 取り込んだファイル名と読み取った明細・金額を表示。工事の条件（工期・工事ができない日・支払い方法）を編集。**見積書の差し替え**もここから |
| 　└ これまでの記録 | 誰がいつ何をしたかの記録 |
| 取引先 | お客様の登録／編集。会社名・所在地・支払条件を管理し、各書類へ自動反映 |

## 実演フロー（この順で最後まで操作できます）

1. **工事案件の一覧**を表示（進行中の案件が多様な状態で並ぶ）。「対応が必要」タイルを押して対象案件だけに絞り込む
2. 「見積書を取り込む」→ 取込待ちのファイル一覧から1件選ぶ → **読み取り中の表示のあと、取引先・工事名・明細・金額が自動で埋まる**
3. 見積書に書かれていない4項目（工期の開始・終了、工事ができない日、支払い方法）を入力
   → 支払い方法は**取引先マスタの支払条件から自動で入っている**
4. 「この内容で登録する」→ 案件詳細へ。進み具合の①が「いまここ」になる
5. 「次にやること」の**「3つの書類を作る」**を押す → 注文書・注文請書・基本契約書（約款）が採番され、見積内容が反映された状態で作成される
6. 「書類」タブで各書類の「書類の中身を見る」→ 記載内容を確認（そのまま印刷も可能）
7. 「押印済みの注文書を受け取った」→「注文請書を送った」→ 進み具合が③契約成立へ進む
8. 「見積書の内容」タブ →「見積書を差し替える」→ **差し替え前後の金額が並んで表示される** → 差し替えると
   「見積書の内容が変わっています」の警告が出るので、**3つの書類を作り直す**
9. 「書類に必要な項目」で不足があれば、「足りない項目を入力する」から工事の条件を入力して解消
10. 「書類」タブ →「1つのファイルにまとめる」→ ファイル構成を確認して出力（記録に残る）
11. 「これまでの記録」タブで操作履歴を確認。「取引先」で会社情報を編集すると、書類の記載へ反映される

> 入力・操作した内容は画面上の状態に即時反映されます。ブラウザを再読み込みすると初期のサンプルデータに戻ります（永続化はしていません）。

## 使用技術

- React 19 + TypeScript
- Vite（`base` をサブパスに設定し、GitHub Pages でそのまま閲覧できる静的ファイルを生成）
- React Router v7（`HashRouter`）
- バックエンド・外部サービスへの依存なし（フロントエンドのみで完結）

## ビルド方法

```bash
npm install
npm run build
```

- ビルド成果物（デモ直下の `index.html` と `assets/`）が公開対象です。`src/` は開発用ソースです。
- `build.outDir` がデモ直下のため、ビルドすると `index.html` が**ビルド後の内容で上書き**されます。
  再ビルドする前に、`index.html` を開発用（`<script type="module" src="/src/main.tsx"></script>` を持つ形）へ戻してください。
- `main` へマージされると GitHub Pages に公開されます。

## データについて

- 表示されている**会社名・担当者名・住所・電話番号・ファイル名・工事内容・金額・日程はすべて架空のサンプル**です。
  会社名は固有部分を「〇〇」で伏せています。
- 取り込み対象の見積書ファイルは、画面上のサンプルデータです（実ファイルの読み込みは行いません）。
- 実在の顧客・案件・個人情報や、認証情報・実データは一切含みません。**顧客固有の実装も含みません。**
- 自社側の会社名「株式会社〇〇製作所」、建設業許可番号、担当者名も架空です。
- 約款の条項・「書類に必要な項目」のチェック内容はデモ用のサンプルであり、法的助言を目的とするものではありません。
  実際の運用にあたっては専門家にご確認ください。
